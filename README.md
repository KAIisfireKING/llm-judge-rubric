# llm-judge-rubric

**一套对抗性 LLM-as-Judge 评分体系，及其多模型交叉评测的实证记录。**

用数学建模竞赛论文作为评测对象，解决一个具体问题：**当被评对象"看起来很专业"时，如何让大模型评委不给出虚高分数。**

---

## 这个项目在做什么

大模型当评委（LLM-as-Judge）有一个已知的系统性偏差：**结构完整、公式密集、排版整齐的内容会被打高分，哪怕内核是错的。** 这是格式偏好偏差（format/length bias）在真实任务上的表现。

本项目针对这一偏差，做了三件事：

1. **设计一套对抗性评分细则（rubric）** —— 立场是"默认怀疑，逼被评对象用证据挣分"，而不是"默认给分再找理由扣"
2. **把评分员与生成器拆成两个独立 agent** —— 生成器不允许给自己打分，从机制上切断自评偏差
3. **用三个不同模型按同一 rubric 盲打同一份材料**，分析分差来源，产出仲裁结论

---

## 关键结果

在一篇真实竞赛论文（2025 国赛 C 题）上，三个模型独立按同一 rubric 打分：

| 评审模型 | 总分 |
|---|---:|
| Fable 5（最高推理） | 81 |
| Sonnet 5（最高推理） | 78.5 |
| GPT（外部） | 68 |
| **仲裁综合分** | **72** |

**分差 13 分，几乎全部来自同一件事**：论文问题四存在"交付物级失效"（正文头条报告 OOF 交叉验证指标，最终提交清单实际是训练内预测，口径不一致；且分类结果 91% 多标签泛滥、不可用）。

- Fable 5 与 Sonnet 5 **均未抓到** → 给出 78.5–81
- GPT **抓到并重罚** → 压到 68

仲裁的做法不是取平均，而是**独立复现该缺陷**确认其真实存在，再判定综合分必须落在 81/78.5 之下、但不必如 68 那样把问题一至三扎实的可复现性一并抹掉 —— **落点 72**。

> 方法论结论：单篇绝对分的漂移可达 ±15，三份打分的跨度 13 分正落在漂移带内。
> **因此可信的是相对排序，而不是任何一个绝对数。**

完整报告见 [`case-study/multi-model-eval-25C.md`](case-study/multi-model-eval-25C.md)。

## 设计要点

### 1. 生成器与评分员严格分离

仓库里是两个互不融合的 agent：

- [`generator/solver-agent.md`](generator/solver-agent.md) —— 生成器，从赛题+数据造出一篇完整论文。**明文规定不自评、不打分。**
- [`rubric/judge-agent.md`](rubric/judge-agent.md) —— 评分员，独立审。

两者刻意分开，避免"谁生产谁验收"。

**一个被主动保留的已知冲突**：生成器按既定风格产出"九宫格流程图"，而评分员会把"三张同构流程图"判为模板化/AI 味并在创新性维度扣分。这个冲突被明确记录、主动接受 —— 是否精简留给人来决定，不在生成阶段纠结。系统性偏差写进文档比藏起来有用。

### 2. Rubric 是从错误分析里长出来的，不是拍脑袋写的

[`rubric/rubric-v2.md`](rubric/rubric-v2.md)（六维 100 分，215 行）的 v2 版本，**每一条新增的硬性动作都对应一次真实的漏检或误判**，来源是两篇实测论文 × 五个独立评审员的交叉解剖。

| 维度 | 分值 |
|---|---:|
| 摘要与整体规范 | 15 |
| 模型建立 | 20 |
| **求解正确性与数据一致性** | **25** |
| 结果解读深度 | 15 |
| 模型检验与稳健性 | 15 |
| 创新性与原创度 | 10 |

每个维度写明"满分长什么样 / 及格长什么样 / 不及格长什么样"，附具体扣分点与正反例，并单独定义**致命伤（红线）**和**常见误判与校准**章节。

### 3. 证据规则：禁止自证循环

细则里最硬的一条纪律：

> **核对数值一律"表 ↔ 代码产出文件"，禁止"表 ↔ 表"。**
> 论文表格之间互相比对只能证明同源，不能证明正确。

这条来自一次真实翻车：某篇论文的表 6 被另一问的数字污染，因为同源复制，骗过了一切表间核对；某个模型报告"核验通过"，实为循环验证。

配套的**量刑纪律**：当评分员拿不到源代码时，"最优性/合理性"类致命伤一律**降级为质疑** —— 因为推理输入本身可能就是那张错表。（实测中确实发生过评审者据被污染的表格误杀了正确模型。）

### 4. 用已知真值锚定分数尺

绝对分不可信，所以引入外部锚点校准：另一篇已知真实获奖等级的论文（真实三等奖）在同一 rubric 下得 63 分，用它把分数尺钉住，再判断待评论文相对它的位置。

### 5. 一套针对 AI 产出的验收协议

[`methodology/output-verification-protocol.md`](methodology/output-verification-protocol.md) 把"如何验收模型产出的数值"写成十条可执行纪律，核心命题一句话：

> **「我又检查了一遍」不是证据。换一条路算出同一个数，才是证据。**

其中几条：

- **退化测试必须预注册** —— 预期结果写在跑代码之前；跑完再补的"预期"只是对已知结果的追认
- **假设风险用反事实变化量定档** —— 换成替代假设后答案变化 <1% 低 / 1–5% 中 / >5% 高，高风险必须做扰动出弹性系数
- **有效数字不得超过稳定性支持的位数**，且禁止声称"验证通过"，只能写"自检通过，以下假设尚未独立验证：…"
- **数量级闸门** —— 偏离数量级是建模的根本性错误，不是调参能解决的
- **不同统计口径禁止同表同行** —— 否则会出现"点值落在自己区间之外"这种直接引发全流程怀疑的画面

### 6. 人机边界作为一等公民

[`methodology/human-ai-boundary.md`](methodology/human-ai-boundary.md) 把"哪些环节必须由人决策、哪些可以交给模型"逐环节列成验收单，核心原则：

> **AI 管表达层（措辞、格式、代码、初稿）；人管思想层（逻辑、论证、判断、取舍）。**

包含一份逐环节介入点清单，标明每个环节的协作盲区（例如：模型会把问题二的数字张冠李戴到问题一；会推荐"看起来合理但不适用"的方法；列出的简化假设可能恰好砍掉问题核心）。
