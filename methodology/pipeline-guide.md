## LaTeX 用哪个 —— MiKTeX，直接写 `xelatex` 就行
- TinyTeX 已经卸了，现在系统里 `xelatex` **唯一指向 MiKTeX**，不用再钉任何路径，裸写 `xelatex` 就对。
- 第一次编到某个新宏包时，MiKTeX 会自动联网下载。已于 2026-07-15 设成**全自动安装**（`AutoInstall=1`），不会再弹窗——AI 在非交互终端里编译时弹窗=卡死，这个坑已焊死。
- 更省心的编译：`python -X utf8 论文/build.py`（两遍编译+自动验收错误行/页数/PDF文本层），或双击 `论文\编译.bat`。
- 中文字体用模板自带的思源宋体（在 `论文/fonts/`），不用管。

## 流程（每道题都这么做）

**Step 0 · 起项目**：把 `mwhite/` 复制一份当这道题的文件夹（如 `mwhite-电工杯B/`）；清掉 `题目/数据/求解/论文` 里的示例内容；赛题放 `题目/`、数据放 `数据/`。

**Step 1a · 生成计划并暂停**（在这个文件夹里开生成会话，模型用 **GPT-5.6-sol**）：
> `先读根目录 AGENTS.md 并全程遵守，再按 CLAUDE.md 方法论执行 Step 0（读题＋全量读数据＋打印数据总览）和 Step 1（写 求解/求解计划.md）。写完计划立即停下等我指令，不要开始求解。`

**Step 1b · 计划会诊（洞察注入点，你人工主持）**——开两个新窗口，你在中间传话：

- **Claude 窗口**（在这个工程文件夹里开，要能跑 Python）：
> `主持求解计划会诊：读 题目/、数据总览和 求解/求解计划.md 草稿。开子 agent 并行探 2~3 条建模路线，关键假设写小脚本快速验证可行性（探路代码一律放 求解/探路/，别污染正式目录），用评审 skill 维度六（创新性）的视角出巧思清单。把你的质疑和替代方案整理成一份"挑战书"给我，我传给 GPT 评审员；拿到它的反驳后你来合成定稿——直接覆盖改写 求解/求解计划.md，文首标注"会诊定稿"、文末加"巧思清单"和"图面规划"两节（图面规划只写方向不写规格：每题主打 hero 图候选＋承载什么数据＋深浅基调，全文深色 hero 图 2~3 张、必须成套），最后把续跑 prompt 写给我。`

- **GPT 新窗口**（对抗评审员，**别用**原生成窗口）：
> `你是数模求解计划的对抗评审员。我会陆续给你题目、求解计划草稿和另一位评审的挑战书。从建模选型是否最优、创新性够不够、实现风险三方面逐条反驳或改进，必须给具体替代方案（模型名＋为什么更好），不许空泛表态。`

- 传话 **≤2 轮**就收（收益递减很快），定稿以 Claude 合成的版本为准。会诊全程你可以随时插自己的想法——这正是全流程里唯一需要人脑的位置。

**Step 1c · 回原生成窗口续跑**：
> `求解/求解计划.md 已会诊定稿（覆盖了你之前的草稿），重新完整读取它，冲突处一律以定稿为准，"巧思清单"一节必须落实到建模和论文里，不得擅自换回原选型。现在从 CLAUDE.md Step 2 开始逐题求解，一路到底到编译出 PDF 不要停。编译用 python -X utf8 论文/build.py（报错别换引擎、别装新 TeX）。每个 Python 脚本开头加两行 UTF-8 wrapper。排版优化只许缩短文字或回 Python 改 figsize 重画，禁改表格环境/图宽/字体。出图守 AGENTS.md 图表质量规矩：每题先画 1 张模型构型/机理图，双参数扫描用热力图，相关视角合成组合图，同类型图每题最多 2 张，全文一套配色；hero 图与深浅基调按定稿"图面规划"执行，图片一律独立成图，.tex 禁止并排。`

为什么这么拆：模型选择、建模巧思、创新点 90% 发生在求解计划这一步，之后全是执行——洞察前置到这里注入，比中途打断便宜且有效；原生成窗口的上下文保持纯执行，讨论过程留在会诊窗口里，互不污染。另外 **GPT/Codex 不会自动读 CLAUDE.md，只自动读 AGENTS.md**，所以每条 prompt 第一句永远是"先读 AGENTS.md"；1c 里后面几句各堵一类实测翻过的车（换 TeX 引擎、中文乱码、为消警告毁排版、十几张同款丑柱状图）。赶时间想跳过会诊，用短prompt速查里的"一把梭"版。

**Step 2 · 评审**（另开一个 **Claude** 会话，要能跑 Python）：
> `用我的评审 skill 给 论文/ 打分。代码在 求解/、结果在 求解/**/结果/。逐题重跑脚本核对论文数值↔csv，对"分配/归属"类结果用下游表反推，对照锚点(电工杯006768B=63分=三等奖)给相对排序，输出致命伤+六维得分+必改清单。`

**Step 3 · 修复**（回生成会话，**GPT-5.6-sol**）——先分清是"小修"还是"大修"：

- **小修**（评审只挑出一两个孤立的数值/文字错、其余全对）：用轻量补丁，见速查区"修复·小修"。
- **大修 / 出版前定稿（默认走这个）**：用**乐高重搭法**——别只把评审报告或几句错处丢给它"哪错改哪"。就像搭乐高，发现搭错了不会只抠出那一块硬塞（很可能扰乱周围、还是错），而是**把现有这版的完整成果（论文/*.tex、求解/*.py、数据、图）连同一份"这版已知的坑"备忘一起给它，从头把流程重跑一遍**——这次带着"哪里容易搭错、正确该是什么样"的明确指示去搭。局部补丁越打越乱，带记忆的整体重跑反而干净。
  > 重搭 prompt（**先存档！** 重跑会覆盖 csv/图，开工前先 git commit＋人工整份复制备份）：`先读根目录 AGENTS.md 并全程遵守。这是一次"带记忆的整体重跑"，不是局部打补丁：工程里已有一版完整论文（论文/*.tex、求解/*.py、数据、图）和一份评审报告。把评审报告的必改清单当作"这一版已知的坑，这次要全部避开"，然后从 CLAUDE.md 的求解流程从头完整重跑——重新算、重新出图、重新写 tex、重新用 build.py 编译，一路到底到 PDF。已经正确的部分沿用现有结论、不必推倒重来，出错的部分按清单的正确口径重做；图守 AGENTS.md 第五~七节图表规矩（含第七节高级图型库：一图一型不重复、贴题才用、总量 3~6 张），排版守七条铁律。开工前先 git add -A && git commit -m 重跑前基线（无 .git 先 git init）。每遍结束用 python -X utf8 论文/build.py 验收，报错别换引擎；交付附对照表：这遍避开/修正了清单哪几条→文件→旧值→新值→来源csv行号。`
  - **最多重跑 3 遍，一般 2~3 遍就收敛**——超过 3 遍是边际收益见底的信号，停下人工看问题在哪，别无脑刷。
  - 若正确性都对、只是图不够高级，走**路径 B·抽卡改图**（执行者用 **Claude**，就用评审那个能跑 Python 的会话——改图是轻约束＋审美驱动的活，跟"GPT 吃严格长约束"的分工正好相反；测试期先这么定，不满意再换 GPT 对照）。抽卡逻辑：高级感本质是抽卡，一次多出几个候选、人来挑，比写死规格靠谱得多：
  1. 抽卡：`照 AGENTS.md 第六~七节图表规矩（含深色 hero 主题），为求解计划"图面规划"选中的 3~5 张 hero 图各生成 2~3 个不同风格的高质感候选（同一数据、只动绘图代码），全部存 求解/问题X/图片/候选/，正式目录一律不动，完成后列清单带文件路径给我挑。`
  2. 你翻一遍候选 PNG 挑中意的（30 秒的事），回复选中哪几张。
  3. 换装：`把我选中的候选替换为正式图：改正式绘图脚本重跑出图（文件名沿用原图），数值/排版/其余图一律不动，git 存基线后 diff 自查，python -X utf8 论文/build.py 重编译验收。`
  - 抽卡**最多 2 轮**；一轮不满意先想想是不是图型没选对（回 AGENTS.md 第七节的匹配思路），别无脑再抽。

修完**你自己花 30 秒**把新旧 PDF 并排翻一遍：图表位置/大小/符号说明表还在不在原位。编译日志干净 ≠ 版面没毁——25-C 实测：数据全对、日志零警告，版面全毁。

改完想再确认，重复 Step 2 打一次分，跟上一版比提了多少。

**Step 4 · 复盘（前 2~3 篇必做，之后可选）**：每跑完一篇论文，把工程根目录 `运行日志.md`（AGENTS.md 第九节要求执行模型凡报错/绕行必当场记：现象原文/绕行方式/隐患根治）丢给 Claude：
> `读 运行日志.md，逐条判断根因：环境问题该修环境、规则空白该补进 AGENTS.md/使用指南、模型偶发不用管。给出修订方案我确认后落实。`

流水线越用越顺靠这个闭环：跑 2~3 轮把坑焊死，之后它一个问题都不会再遇到。

## 我的几条叮嘱
1. **LaTeX 就认 `xelatex`（=MiKTeX）**，别再碰 TinyTeX（已卸）。编译报字体错，就让 AI 把 format.cls 里的字体名换成 Windows 有的（Menlo→Consolas，我已帮你改好，换新模板时留意）。
2. **生成用 GPT-5.6-sol**（听话、吃长约束、超预期）；**评审和拍板用 Claude**（当评委、做判断、决定重抽还是修）。
